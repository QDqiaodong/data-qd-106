# 纯分析月度趋势协议（recall-collect-trends/1）

`recall_collect.trends.summarize_monthly(rows, start_month, end_month)`
是纯分析函数：只在内存中对**调用方传入的、已接受的公告记录**做统计，
不打开数据库、不读取四份工厂 CSV、不访问公告站，也不修改任何输入。

## 1. 输入记录形状

每条记录是恰好含以下五个字段的映射，与公告解析器
（`recall_collect.site.notice`）及影响集市只读快照
（`recall_collect.impact.sources.read_recall_tables`）产出的形状一致：

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| `recall_id` | 非空字符串 | 公告身份，整批输入内不得重复 |
| `published` | `YYYY-MM-DD` 字符串 | 发布日期，必须通过 `date.fromisoformat` 往返校验，拒绝紧凑/非规范形式 |
| `product` | 非空字符串 | 公告产品原文，按精确文本比较 |
| `lots` | 非空字符串**列表** | 公告批号；元素为非空字符串 |
| `reason` | 非空字符串 | 原始原因文本，按精确文本分组，不 trim、不改大小写、不规范化 |

直接取自 SQLite `recalls` 表的行把批号存在 `lots_json` 列；调用方须先用
`json.loads` 还原成 `lots` 列表（`read_recall_tables` 已这样做）。
记录字段集合必须与上表**完全一致**，多字段或缺字段均拒绝。

## 2. 统计粒度与日期口径

* 月份参数格式为 `YYYY-MM`，`start_month`、`end_month` 首尾均包含。
* 月份键按 `published` 的日历月归月（`published[:7]`，该字符串已通过
  ISO 日期往返校验）；区间内没有公告的月份仍输出一条零值记录。
* 区间外记录被**忽略**，不进入任何计数；但区间外记录本身若非法
  （含重复 `recall_id`），仍使整次调用失败——校验先于过滤。
* 逐月、按时间升序返回，字段固定为：
  - `announcement_count`：该月公告数（一条记录算一个公告）。
  - `announcement_lot_pairs`：公告–批号对数，口径是
    （公告, 批号）去重计数。同一公告内重复批号只计一次；不同公告
    即使批号相同也分别计数。
  - `distinct_products`：该月不同产品数，按 `product` 精确文本去重。
  - `reason_counts`：按**原始 reason 精确文本**分组的公告数；
    键按 Unicode 码点排序，因此输出与输入行序无关。
* 每条公告在其所属月份恰好贡献 1 个公告数、N 个批号对（N 为该公告
  去重后批号数）以及 reason 分组中的 1 次，逐组计数之和恒等于当月
  公告数，可据此做总数对账。

## 3. 失败约定（不返回部分结果）

所有输入在任何聚合发生之前完成校验，任一错误都抛出
`TrendInputError`（`ValueError` 子类），已计算的中间结果不会返回：

* 非法月份：非字符串、不符合 `YYYY-MM`、月份超出 01–12。
* 反向区间：`start_month` 晚于 `end_month`。首尾相同的单月区间合法。
* 重复 `recall_id`：内容相同也拒绝，且对全部输入（含区间外记录）检查。
* 无效记录：非映射、字段集合不符、文本字段为空或非字符串、
  发布日期非法、`lots` 不是非空字符串列表。

函数不修改输入记录（不改写、不去重、不排序调用方的列表），
也不依赖输入行序：同一批记录任意排列得到字节级一致的输出。

## 4. 边界与来源约束

* 本模块只依赖标准库，不引入新的运行依赖，不改变包的公开采集入口、
  采集库表结构（`recalls`/`sources`）及影响集市的任何表与传播口径。
* 函数不做任何 I/O，因此可在无数据库、无 CSV、无站点夹具的环境直接
  单测；合成记录由测试自行构造，期望值手工核算，不由被测函数生成。
