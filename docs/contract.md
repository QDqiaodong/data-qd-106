# 公告站协议

输入是调用方控制的本地模拟站目录，入口 index.html。不是某个真实监管站适配器。
HTML 的 a[rel=next] 遍历列表页，a[rel=notice] 指向详情；循环链接只读一次。
详情脚本 type=application/json，字段 recall_id/published/product/lots/reason 严格匹配。
日期为 ISO 日，lots 为非空字符串数组，排序去重；其余文本原样保存。
同一 recall_id 的内容必须一致，不支持修订。跨页面重复不重复入库。
recalls 表保存召回/产品/批号/原因；sources 表保存源站相对文件路径，可查来源。
只接受根目录内 HTML，拒绝外链、查询串、片段和越界路径（包括符号链接越界），单页上限1MB。
源站应只放公开或合成文件，本站 fixture 全为合成。最多1000页，全量读入后事务入库。
存在内容冲突时整批数据回滚；已有数据保留。失败时新建空库/表可能存在。
不发起网络请求，不涉及真实接口或第三方使用条件。数据库重复采集 inserted=0。

根内符号链接及根内绝对文件路径允许，来源路径按解析后的规范文件位置记录；
同一文件的多个别名只解析一次。交付fixture只使用相对链接，不含绝对路径或符号链接。

## 输入捕获与竞态边界

采集不按"先 stat 校验、再按路径读取"的分离步骤工作。每个规范页面在一次
`os.open` 得到的文件描述符上完成全部校验与读取，实际解析的字节与校验对象
绑定为同一 inode，且每个规范页面全程只捕获一次：

- 打开后以 `fstat` 确认是常规文件；随后按 64KiB 分块读取并在**实际读到的
  字节数**上执行 1MB（1,000,000 字节）上限：恰好 1MB 接受，多读一个字节即
  拒绝，因此校验后增长的文件无法绕过上限。不以重复 stat 缩小时间窗口。
- 打开使用 `O_NOFOLLOW`（平台支持时），检查后把页面替换为符号链接会在打开
  处直接失败；读取结束后再对路径做一次 `realpath` + `samefile`/inode 复核，
  检查后把页面或其父目录替换为根外链接同样拒绝，根外字节不会进入解析器。
- 全部读取到的字节先按 UTF-8 完整解码（跨分块的多字节字符可正确重组，
  截断的多字节序列显式 `UnicodeDecodeError`），再交给 HTML 解析器。
- 详情页非空检查复用首次捕获的同一份文本，不存在第二次文件读取；别名与
  循环链接仍只算一个规范页面（`seen` 去重，上限1000页语义不变）。

校验或捕获失败在打开目标数据库之前抛出，已有库内容与表结构保持不变；
本协议不保证多个文件之间的跨文件原子快照，只保证单个被解析页面的
"校验对象＝解析内容"。测试通过模块级同步注入点（非线程、非 sleep）在
校验后、读取前稳定复现页面替换、父目录替换、读取中超限增长与两次读取
分歧，旧实现快照见 tests/legacy_site.py，对应缺陷复现见
tests/test_legacy_race.py。
